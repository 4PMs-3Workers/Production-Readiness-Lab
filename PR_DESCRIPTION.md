## Technical Implementation Details

### Async SQLAlchemy Support
The migration environment (`env.py`) uses proper async patterns:
```python
async def run_migrations_online_async():
    connectable = create_async_engine(url, poolclass=pool.NullPool)
    async with connectable.connect() as connection:
        await connection.run_sync(_run_migrations_with_connection)
    await connectable.dispose()
```
This ensures compatibility with `mysql+asyncmy://` URLs without `MissingGreenlet` errors.

### MySQL-Specific Optimizations
- `BINARY(32)` for fixed-size hashes (instead of `BLOB`) to support UNIQUE constraints
- `DATETIME(6)` for microsecond precision timestamps
- `utf8mb4_0900_ai_ci` collation for proper Unicode handling
- Explicit table options: `ENGINE=InnoDB CHARSET=utf8mb4`

### Migration Safety
- Hand-authored migration (not autogenerated) for full control
- Comprehensive check constraints for data integrity
- Descriptive names for all constraints and indexes
- DESTRUCTIVE downgrade warning in migration docstring
