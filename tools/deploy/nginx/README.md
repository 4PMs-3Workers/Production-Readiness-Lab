# Gateway overlay contract

Select exactly one overlay with `tools/deploy/compose.yaml` as the first file:
`compose.local.yaml` for local HTTP, or `compose.https.yaml` for HTTPS. Run Compose
from the repository root with `-f tools/deploy/compose.yaml -f tools/deploy/compose.local.yaml`
(or replace the second file with `compose.https.yaml`).

All modes require paths to four external raw env files: `PRL_DB_ENV_FILE`,
`PRL_RUNTIME_ENV_FILE`, `PRL_MIGRATION_ENV_FILE`, and `PRL_SEED_ENV_FILE`.
Unused migration/seed files may be empty until those explicit jobs are invoked.
Runtime secrets belong in the external runtime file; never interpolate them into
Compose YAML or commit the files. Diagnose configuration with `config --quiet`
or `config --no-env-resolution` only. Plain `config` expands secret env values.
Migration, grants, and schema verification must precede business traffic; the
base Compose file defines these explicit jobs.

Local mode binds `127.0.0.1:${PRL_HTTP_PORT:-8080}` with the matching application
origin `http://localhost:<port>`. Browse using `localhost` so Origin checks match.
Local mode explicitly permits non-Secure, host-only cookies for local HTTP.

HTTPS requires `PRL_HTTPS_ORIGIN` to be the exact browser origin, including any
nondefault port; for example `https://localhost:8443`. Supply absolute external
paths in `PRL_TLS_CERT_FILE` and `PRL_TLS_KEY_FILE`. The certificate must cover the
browser hostname and chain to a browser-trusted CA. The unencrypted private key
must be readable by container UID/GID 101; keep host permissions as narrow as the
runtime permits. Missing bind files fail closed rather than creating directories.
No certificate or key is supplied or generated by the application. Tests generate
short-lived self-signed material only in the OS temporary directory and validate
its localhost certificate using an explicit trust context.

HTTPS binds `127.0.0.1:${PRL_HTTPS_PORT:-8443}` by default. Set `PRL_HTTPS_BIND`
explicitly for a remote demonstration, and keep the public origin consistent.
HTTPS sets Secure, host-only, SameSite=Lax cookies. Neither mode publishes API,
frontend, or database ports. The health endpoint `/health/gateway` proves Nginx
liveness only; `/health/ready` checks API readiness.

Only API and gateway join the internal `172.30.34.0/29` gateway network.
The API trusts only gateway peer `172.30.34.2/32`. This fixed subnet must
be available on the Docker host; simultaneous stacks need different coordinated
subnets and peer settings. Do not widen trust to the shared frontend network.
Nginx replaces client-supplied forwarding metadata. The API accepts one
canonical `X-Forwarded-For` address and one `X-Forwarded-Proto` value
(`http` or `https`) only from that trusted peer. Malformed or missing values
fall back independently to the socket peer or original scheme. Request-ID
trust still uses the immediate peer. Origin, Referer, Cookie, CSRF, and
idempotency headers are preserved. API errors and Retry-After pass through;
gateway failures return sanitized JSON with an ID. Exact and trailing-slash
login paths share the Nginx login rate zone and 4096-byte body limit; other
requests allow 32768 bytes. The backend login quota uses the validated client
address for gateway traffic and the socket peer for direct traffic. Connect
timeout is 2 seconds;
proxy read/send and client body/header timeouts are 10 seconds.

Access logs contain method, normalized path without query, status, duration and
request ID. Do not put secrets in URL path segments. Headers, query strings and
bodies are excluded; error logging is restricted to critical startup/runtime
failures. This is a local deployment smoke foundation, not production acceptance.

Run gateway acceptance with `RUN_GATEWAY_TESTS=1 python -m pytest tests/containers/test_gateway.py -q`.
It uses real pinned Nginx and merged overlays with controlled upstream processes
and the real cookie, CSRF, Origin and request-ID policies. Full application login
and persistent database acceptance belongs to the later Compose smoke suite.
