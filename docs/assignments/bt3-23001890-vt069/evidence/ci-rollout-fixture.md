- Pull request: #66, initial failing head `222a8ae39a0b5f99d98191bcb7caa5004fffde42`.
- Remote job: `Serialized deployment and verified rollback`, step `Required isolated Linux rollback and committed-data proof`. Two duplicate workflow runs reported the same failure. The job log showed `tests/rollout/test_configuration_transition.py::test_reviewed_configuration_upgrade_and_rollback_preserve_the_existing_host`, at `RolloutStack.start()`, `AcceptanceFailure: Fixture schema failed`; each run reported 1 failed, 3 passed. This was after the container fixture schema command, before the old host was started.
- First root cause: `Artifacts.manifest(..., root=base)` built a release manifest for an archived predecessor tree, but assigned module-global current `SCHEMA` (`20261113_1200_booking_quota`). The predecessor release source declares `20261019_1200_proposal_replay`, so its schema service rejected the fixture contract.
- First test/fix: `test_manifest_uses_schema_revision_from_selected_source_tree` caught the mismatched revision; commit `6b1de05` changed manifest construction to read the pin from the selected source tree. The focused group passed 78 tests.
- Second CI failure on head `2a486313c276335567d0a55646b8cc9a96961427`: the old host proceeded further, then `render(manifest, root=base)` called `require_compatible`, which still compared against module-global current `SCHEMA` and raised `ReleaseError("incompatible-schema")`. The same rollback test failed at `RolloutStack(..., root=base)` while rendering the predecessor manifest. This confirms the first fix removed the startup schema failure but the manifest renderer still had a separate global-schema assumption.
- Extended RED: the same regression test now invokes `render(manifest, root=legacy_root)` and asserts the emitted `ACCEPTED_SCHEMA_REVISIONS` uses the predecessor value. It failed at `require_compatible` with `incompatible-schema`, not at setup/import.
- Follow-up fix: centralize reading the exact `SCHEMA` assignment from the selected tree in `tools/deploy/release_manifest.py`; use it both in `require_compatible` and the renderer's emitted schema environment. `Artifacts.manifest()` uses the shared helper.
